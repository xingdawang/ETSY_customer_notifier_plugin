# Etsy 消息哨兵 v0.1.0

Chrome / Edge 的 Manifest V3 扩展。沿用 `ETSY_review_collector` 的网页右侧可收起面板，并提供工具栏弹窗和独立邮箱管理页。无需打包构建即可加载。

## 安装与使用

1. 下载发布 ZIP，先解压到固定目录。也可直接加载本仓库根目录。
2. Chrome 打开 `chrome://extensions/`，Edge 打开 `edge://extensions/`，开启开发者模式。
3. 点击“加载已解压的扩展程序”，选择**直接包含 manifest.json 的目录**。最低 Chromium 版本为 120；推荐使用当前稳定版 Chrome / Edge。
4. 刷新已经打开的 Outlook / Gmail 页面。右侧会出现“Etsy 消息哨兵”，可以收起为圆形按钮。
5. 打开收件箱。插件识别实际邮箱后，填写店铺名称，点击“绑定当前邮箱并监听”。如果无法识别账号，请手动打开邮箱右上角头像菜单，让页面显示当前邮箱地址。
6. 首次扫描仅建立当前列表基线，不把旧邮件当成新消息。后续匹配邮件会出现在管理页的“消息记录”。
7. 点击浏览器工具栏的扩展图标打开弹窗，再点击“打开邮箱管理”，查看邮箱、状态、记录、日志和设备设置。

建议每个浏览器配置文件固定使用一个邮箱。一个浏览器中也可添加多个邮箱，但每个实际邮箱都必须有可访问且账号匹配的收件箱页面。Gmail 的 `/u/0` 序号、浏览器登录账号都不作为邮箱身份。

## 已实现

- Outlook.com / Hotmail / Live，以及 Gmail / Google Workspace 网页适配器；同时匹配 Outlook Office 网页主机，但尚未对企业邮箱视图进行实机验证。
- 可收起的页面面板、工具栏弹窗、独立管理界面；添加、改名、暂停、恢复、移除和打开邮箱。
- 列表变化检测和每 30 秒检查；Service Worker 使用 alarms 唤醒，重启时检查调度是否存在。
- 实际账号核对、账号切换阻断、收件箱范围检查、页面关闭 / 无响应 / 休眠 / 状态过期识别。
- 英文 Etsy 买家会话及订单求助主题分类；只显示 Etsy 名称时标记为“候选、待核实”。有明确非 Etsy 发件地址时拒绝分类。
- 首次基线、稳定邮件 ID 优先去重、会话修订或元数据特征后备去重；不使用未读状态或主题单独去重。
- 本地持久事件队列、历史记录、日志和 JSON 导出；可选浏览器桌面通知。
- 中央 v1 协议客户端：设备配对、心跳、事件批量上报、明确确认、失败退避、凭证失效后重新配对，以及测试邮件验证结果上报。

## 必须理解的运行边界

这是**网页监听版**，尚未使用 Graph 或 Gmail API。适配器和浏览器流程已使用隔离模拟页面验证，真实邮箱页面的兼容性仍需逐平台验收，不能据此承诺一分钟内无漏报。

- 只读取已渲染邮件列表元数据，不打开正文，不下载附件，不标记已读，不修改邮件。收件箱外、Outlook 的其他分类、未加载列表和折叠会话可能没有覆盖。
- 日期无法解析、没有逐邮件标识时，去重能力降低。同一会话在缺少时间和计数变化时连续来信，可能无法分辨；滚动加载且时间未知的旧行，也可能产生候选记录。
- Outlook 列表可能只显示发件人名称。只有已知主题加 Etsy 名称时才能产生弱识别候选；只有主题、缺少发件人证据时不提醒。
- 如果邮箱地址仅出现在头像菜单中，插件可沿用本次文档中识别到的账号，但仅限账号按钮特征和账号路由一致。页面重载或特征变化后重新识别。这不是邮箱服务提供的身份认证。
- 后台或最小化并不一定停止检测，但冻结、丢弃、休眠和网络断开都会影响它。扩展不会抢焦点、自动重开用户关闭的页面或自动操作邮箱登录。
- 离线期间本地尚未观察到的邮件，不能保证恢复后完整补收。不能用“页面可读”代替“全量收信正常”。
- 浏览器退出后，扩展不能自行向远端报告。远端失联判断必须由独立运行的中央任务执行。
- 数据保存在当前浏览器配置文件；卸载扩展或清除扩展数据会删除它。页面显示最近 300 条事件；已完成 / 本地历史最多约 2,000 条，未上报记录保留。每个邮箱的观察去重账本最多 5,000 项。

如果业务验收需要完整补收和更稳定的逐邮件标识，下一阶段应加入 Graph / Gmail API，而不是扩大网页模式的可靠性承诺。

## 中央网站与飞书

**配套中央邮件网站尚未实现插件 v1 接口。** 本轮只增加扩展，没有修改现有服务器行为；填写现有地址不会自动获得可用的配对码。

未配对时，消息状态是“仅本地”，不会发送到中央或飞书。配对后的新消息持久入队；只有收到中央明确确认才显示“已上报”，这也**不代表飞书已发送**。配对之前的本地历史不会自动上传。

本地仍有待上传事件时，禁止更换中央网站或直接断开，避免静默丢失队列；允许向同一个网站重新配对来恢复失效凭证。远端凭证的撤销由将来的中央管理页承担；插件“断开连接”只清除本地凭证。

中央接入详见 [PROTOCOL.md](PROTOCOL.md)。插件已支持验证请求，但不会自行发送测试邮件；只有中央在后续心跳明确确认验证结果后，才会显示收信“已验证”。

## 权限与隐私

- 必需：`alarms` 和指定 Outlook / Gmail 主机的访问权限；本地保存使用扩展自身来源的 IndexedDB，无需额外存储权限。
- 可选：用户点击开启桌面提醒时才请求 `notifications`；用户配对中央网站时才请求该主机访问权限。
- 不申请所有标签页历史、Cookie、调试器、网络拦截或密码访问权限，不包含远程代码和统计 SDK。
- 设备令牌只保存在扩展自身来源的 IndexedDB；内容脚本所在的邮箱来源无法直接读取它，通过受限消息只获取去掉凭据、验证码和心跳挑战的公开状态。
- 只上传匹配事件、系统验证结果和绑定邮箱的健康元数据，不上传其他邮件列表或正文。初始阶段的弱分类仍可能误判，所以消息元数据也应按私人数据管理。
- 远端网站必须是可信 HTTPS；本机测试允许 `http://localhost` 和 `http://127.0.0.1`。不绕过无效证书。

## 开发验证

无生产依赖，无构建步骤。Node 20 或更新版本执行：

```sh
node --test tests/core.test.cjs tests/worker.test.cjs
```

运行 `npm install` 和 `npx playwright install chromium` 后，可执行真实扩展加载与模拟页面测试（使用隔离配置文件，不访问真实邮箱）：

```sh
npm run test:browser
```

可用 `MW_BROWSER_PATH` 指定支持加载开发扩展的 Chromium 可执行文件。截图输出到 `artifacts/screenshots/`。浏览器验证不替代 Windows 上 Chrome / Edge 的真实邮箱验收。

打包：

```sh
python3 tools/package_extension.py
```

生成 `dist/etsy-message-sentinel-v0.1.0.zip`，包含可直接加载的扩展文件，不含测试、工具、截图、服务器凭据或本地数据。
