# Etsy 邮件提醒 · 轻量插件 v0.3.2

## v0.3.2 邮箱休眠误报修复

- 对仍在内存中的邮箱页执行有超时的采集探测。即使 Chrome 返回 `frozen: true`，页面能正常响应时也以真实采集结果为准；只有探测失败时才按冻结标记报告休眠。已被丢弃的页面仍报告休眠。
- 页面身份复核同样限制为 2.5 秒，避免一个无响应页面拖住后续心跳和检测。
- 插件重新加载导致旧页面脚本失效时，显示“当前邮箱检测已停止”和刷新按钮，隐藏旧的连接浮层；不再在浮层消息处理中调用已失效的 `runtime.getURL()`。
- 保留原目录、安装身份、设备令牌、去重记录和待上传队列；更新并重新加载插件后，刷新对应邮箱页面。无需解除绑定或重新安装。

Chrome / Edge Manifest V3 扩展。登录界面从上到下显示中央服务器地址、插件账户、密码和连接按钮；连接后显示账户、连接结果和退出；邮箱页面右侧可收起，工具栏弹窗使用同一界面。

这里的账户和密码是**中央服务器预先分配给每个插件的专用凭证**，用于区分插件和验证在线心跳，与邮箱密码、中央网站用户登录无关。

## 使用

1. 解压插件，在 `chrome://extensions/` 或 `edge://extensions/` 开启开发者模式，加载直接包含 `manifest.json` 的目录。
2. 打开已经登录的 Outlook / Gmail 收件箱，刷新一次。
3. 在小面板输入该插件的账户、密码，点击“连接”。凭证必须由中央服务器实际验证。
4. 验证成功后显示“已连接”和账户。后台使用中央配置的归属邮箱、建立初始列表基线、发现新的 Etsy 买家消息并上报，无需填写店铺名称或手动绑定。
5. 退出后停止本机采集并清除会话令牌；网络断开时也可退出。未确认事件按原插件身份保留，不会转给新凭证。

中央服务器地址默认预填 `https://feishu-push.etsyweb.com`，放在账户输入框上方；已保存的自定义地址会保留，也可手动修改。面板收起后显示“哨”，按住气泡可拖到页面任意位置；松手后记住位置，刷新后恢复，窗口变小时自动保持可见。单击气泡可重新展开。

## 中央服务器接入

**中央网站已实现兼容接口。** 自建其他服务时必须支持 [PROTOCOL.md](PROTOCOL.md) 的专用凭证协议 v2，不能把普通网站登录或旧配对接口当作验证成功。没有中央接口或凭证不匹配时，插件不会显示已连接。

中央服务器预设 `插件账户 → 密码哈希、稳定 device_id、启用状态`。验证成功返回有期限、可撤销的设备令牌；插件只保存令牌，不保存账户密码。后台约每 30 秒发送新心跳，中央独立判断失联。通知归属优先使用中央账户保存的邮箱；留空时才使用页面识别地址，不需要在插件填写店铺名称。

界面不展示网页状态；后台仍将必要的邮箱检查结果传给中央，用于区分“插件有心跳”和“邮箱可以检查”。“已连接”仅表示专用凭证已验证且最近能与中央通信。

## 保留的后台能力

- Outlook / Gmail 当前可见收件箱列表的元数据检测，不读正文、不下载附件、不自动回复。
- 新版中央服务协商成功后，上报 Etsy 候选元数据，买家会话、订单求助和非买家邮件由服务器判断；旧服务器仍使用本地英文规则。只有显示名称证据时标记低置信度候选。
- 首次基线、逐邮件标识优先去重、稳定事件编号、持久队列、明确接收确认及自动重试。
- 插件身份隔离：不同凭证的队列和基线分开，更换凭证不会误报旧身份的数据。
- 心跳、页面关闭 / 无响应等必要后台检查。没有手动检查、邮箱管理、店铺名称、日志界面、配对码或桌面通知设置。

这是网页监听方案：需要浏览器和收件箱保持运行。休眠、页面冻结、未渲染邮件、折叠会话、其他分类和网页结构变化仍可能影响检测。真实 Outlook/Gmail 与 Windows Chrome/Edge 需要实测，不能承诺无漏报。无法识别邮箱身份时，可手动打开邮箱头像菜单显示完整地址。

## 凭证与权限

凭证表单位于扩展自身来源的页面，网页浮层只是嵌入该页面；邮箱网站脚本不能直接读取密码输入框。密码仅在用户点击连接时发送给配置的中央地址，提交后清空，失败也不保存。令牌和队列位于扩展自身来源的 IndexedDB，不向邮箱内容脚本返回。

仅使用 `alarms` 和指定邮箱主机权限；连接自定义中央地址时才请求对应主机访问权限。远端必须是可信 HTTPS，本机测试允许 localhost / 127.0.0.1 的 HTTP。安装包不包含测试证书或任何真实凭证。

v0.1 升级会归档旧状态，要求重新输入插件专用凭证；旧配对令牌不复用，旧队列不自动转移身份。

## 开发

Node 20+：

```sh
npm test
```

运行 `npm install`、`npx playwright install chromium` 后进行浏览器测试；测试使用 Playwright、Chromium 和 OpenSSL，生成临时 TLS 证书及本地模拟中央服务，在隔离配置中验证真实凭证交互和两个模拟邮箱。测试完成后删除临时配置及密钥，不连接真实邮箱或中央服务器：

```sh
npm run test:browser
```

可用 `MW_BROWSER_PATH` 指定 Chromium。预览位于 `artifacts/screenshots/`。

打包：`python3 tools/package_extension.py`，输出 `../outputs/etsy-message-sentinel-v0.3.1.zip`。

## v0.2.3 Outlook 兼容修复

支持以 `/mail/?culture=...` 或 `/mail/0/` 打开的默认邮箱入口，结合当前选中的中文、繁体中文或英文收件箱判断，避免把搜索和其他文件夹当作收件箱。邮箱身份优先读取账户组件，补充读取文件夹树的账户标题；不使用邮件发件人推断账户，地址截断或多账户无法区分时保持待识别。若仍未识别，请展开右上角头像菜单，让完整地址显示；不能确认真实地址时不会假装开始监听。

识别到邮箱但尚不在可扫描列表时也会上报具体状态，首次真正扫描仍只建立基线，不推送旧邮件。此修复经过合成 DOM 和隔离浏览器测试；各电脑上的实际页面需要更新后确认。

更新解压式插件时覆盖原插件目录，再在扩展管理页点击重新加载，并刷新邮箱页面；保留原目录和浏览器配置，避免产生新的安装身份。

## v0.3.1 中央管理

- 网站先部署兼容服务，再升级插件。v2 接口保留，0.2.x 不受影响。0.3.0 保留 schema 2 的安装身份、设备令牌、待上传队列和去重基线；在原目录覆盖并重新加载后刷新邮箱页面即可，正常情况下不必重新登录或解除绑定。
- 通过验证身份的 HTTPS 心跳响应协商 schema 1 配置：只接受 30/60 秒定期检测和 etsy_metadata 模式。未知版本、无效配置保留最后有效配置；没有中央配置的旧服务使用原有本地分类。页面变动仍可触发更早扫描，心跳每 30 秒；并非送达时限保证。
- Etsy 候选范围固定为 Etsy 域发件人，或者没有地址时精确匹配 Etsy / Etsy Conversations / Etsy Messages 显示名。仅增加这部分邮件的主题等元数据上报，其他私人邮件不上传。显示名并非发件人认证。
- 非买家候选服务器持久记录过滤回执并确认上传，插件不会无限重试。规则改动只影响尚未处理的新候选，不追溯补发已过滤或初始基线的旧邮件。候选自身的分类规则只改服务器；新增发件域、页面采集能力仍需插件更新。
- 网站账户详情显示页面故障分类、可见行数、插件版本和配置版本。诊断不包含完整网页、页面 URL、正文、附件或密码；离线时展示最后一次快照。
- 网站可下发唯一允许的 rescan 操作。绑定令牌验证、UUID、5 分钟有效期，本地记录完成编号；重试幂等，不清空基线、不刷新/打开邮箱、不自动登录。浏览器崩溃时可能重复一次只读检测，无重复事件通知。
- 远程配置不包含 JavaScript、CSS 选择器、表达式或任意操作脚本。当前未实现远程修复 DOM 解析器，也未接入商店自动更新。开发者模式安装不能通过 GitHub 推送自动升级。
- 上线前先验证少量真实 Windows Chrome/Edge 和 Outlook/Gmail。网页结构、休眠、隐藏分类以及未渲染列表仍限制覆盖范围。

## v0.3.1 会话追加消息与中央邮箱归属

中央账户保存的邮箱通过已认证的登录/心跳下发，作为通知归属；留空时才使用页面识别地址。该地址是运营配置，不是邮箱登录验证，不能据此证明当前页面登录了预期邮箱。每个插件账户应只打开对应的收件箱，避免把其他邮箱归入该账户。

Gmail 优先读取最新邮件 ID，而非会话首封邮件 ID；缺少最新 ID 时用会话 ID、邮件时间和会话数量识别变化。重复扫描、已读/未读变化不触发重复提醒。无法取得新 ID、时间和数量变化时，网页方案仍可能漏报。

从 0.3.0 升级时保留设备令牌和待上传队列，Gmail 首次可读扫描重新建立基线，不补历史邮件。更新扩展后刷新邮箱标签页，让新采集脚本生效。服务器保留检测与入库时间，便于定位延迟；邮箱页面仍需保持运行。
