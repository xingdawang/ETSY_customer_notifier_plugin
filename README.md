# Etsy 邮件提醒 · 轻量插件 v0.2.3

Chrome / Edge Manifest V3 扩展。登录界面从上到下显示中央服务器地址、插件账户、密码和连接按钮；连接后显示账户、连接结果和退出；邮箱页面右侧可收起，工具栏弹窗使用同一界面。

这里的账户和密码是**中央服务器预先分配给每个插件的专用凭证**，用于区分插件和验证在线心跳，与邮箱密码、中央网站用户登录无关。

## 使用

1. 解压插件，在 `chrome://extensions/` 或 `edge://extensions/` 开启开发者模式，加载直接包含 `manifest.json` 的目录。
2. 打开已经登录的 Outlook / Gmail 收件箱，刷新一次。
3. 在小面板输入该插件的账户、密码，点击“连接”。凭证必须由中央服务器实际验证。
4. 验证成功后显示“已连接”和账户。后台自动识别邮箱、建立初始列表基线、发现新的 Etsy 买家消息并上报，无需填写店铺名称或手动绑定。
5. 退出后停止本机采集并清除会话令牌；网络断开时也可退出。未确认事件按原插件身份保留，不会转给新凭证。

中央服务器地址默认预填 `https://feishu-push.etsyweb.com`，放在账户输入框上方；已保存的自定义地址会保留，也可手动修改。面板收起后显示“哨”，按住气泡可拖到页面任意位置；松手后记住位置，刷新后恢复，窗口变小时自动保持可见。单击气泡可重新展开。

## 中央服务器接入

**当前仅完成插件客户端，原 Python 邮件网站没有这些接口。** 必须先让中央服务支持 [PROTOCOL.md](PROTOCOL.md) 的专用凭证协议 v2，不能把普通网站登录或旧配对接口当作验证成功。没有中央接口或凭证不匹配时，插件不会显示已连接。

中央服务器预设 `插件账户 → 密码哈希、稳定 device_id、启用状态`。验证成功返回有期限、可撤销的设备令牌；插件只保存令牌，不保存账户密码。后台约每 30 秒发送新心跳，中央独立判断失联。邮件来源用自动识别的邮箱地址区分，不需要店铺名称。

界面不展示网页状态；后台仍将必要的邮箱检查结果传给中央，用于区分“插件有心跳”和“邮箱可以检查”。“已连接”仅表示专用凭证已验证且最近能与中央通信。

## 保留的后台能力

- Outlook / Gmail 当前可见收件箱列表的元数据检测，不读正文、不下载附件、不自动回复。
- 英文 Etsy 买家会话与订单求助主题识别；只有显示名称证据时标记低置信度候选。
- 首次基线、逐邮件标识优先去重、稳定事件编号、持久队列、明确接收确认及自动重试。
- 插件身份隔离：不同凭证的队列和基线分开，更换凭证不会误报旧身份的数据。
- 心跳、页面关闭 / 无响应等必要后台检查。没有手动检查、邮箱管理、店铺名称、日志界面、配对码或桌面通知设置。

这是网页监听方案：需要浏览器和收件箱保持运行。休眠、页面冻结、未渲染邮件、折叠会话、其他分类和网页结构变化仍可能影响检测。真实 Outlook/Gmail 与 Windows Chrome/Edge 需要实测，不能承诺无漏报。无法识别邮箱身份时，可手动打开邮箱头像菜单显示完整地址。

## 凭证与权限

凭证表单位于扩展自身来源的页面，网页浮层只是嵌入该页面；邮箱网站脚本不能直接读取密码输入框。密码仅在用户点击连接时发送给配置的中央地址，提交后清空，失败也不保存。令牌和队列位于扩展自身来源的 IndexedDB，不向邮箱内容脚本返回。

仅使用 `alarms` 和指定邮箱主机权限；连接自定义中央地址时才请求对应主机访问权限。远端必须是可信 HTTPS，本机测试允许 localhost / 127.0.0.1 的 HTTP。安装包不包含测试证书或任何真实凭证。

v0.1 升级会归档旧状态，要求重新输入插件专用凭证；旧配对令牌不复用，旧队列不自动转移身份。

## 开发

Node 20+：

```sh
npm test
```

运行 `npm install`、`npx playwright install chromium` 后进行浏览器测试；测试使用 Playwright、Chromium 和 OpenSSL，生成临时 TLS 证书及本地模拟中央服务，在隔离配置中验证真实凭证交互和两个模拟邮箱。测试完成后删除临时配置及密钥，不连接真实邮箱或中央服务器：

```sh
npm run test:browser
```

可用 `MW_BROWSER_PATH` 指定 Chromium。预览位于 `artifacts/screenshots/`。

打包：`python3 tools/package_extension.py`，输出 `dist/etsy-message-sentinel-v0.2.3.zip`。

## v0.2.3 Outlook 兼容修复

支持以 `/mail/?culture=...` 或 `/mail/0/` 打开的默认邮箱入口，结合当前选中的中文、繁体中文或英文收件箱判断，避免把搜索和其他文件夹当作收件箱。邮箱身份优先读取账户组件，补充读取文件夹树的账户标题；不使用邮件发件人推断账户，地址截断或多账户无法区分时保持待识别。若仍未识别，请展开右上角头像菜单，让完整地址显示；不能确认真实地址时不会假装开始监听。

识别到邮箱但尚不在可扫描列表时也会上报具体状态，首次真正扫描仍只建立基线，不推送旧邮件。此修复经过合成 DOM 和隔离浏览器测试；各电脑上的实际页面需要更新后确认。

更新解压式插件时覆盖原插件目录，再在扩展管理页点击重新加载，并刷新邮箱页面；保留原目录和浏览器配置，避免产生新的安装身份。
